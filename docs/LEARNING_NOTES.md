## Phase 1: Project Setup

### How a Next.js project is laid out
- `package.json`: project name, **scripts** (`npm run <name>`), and dependencies.
  - `dependencies` are needed at runtime (`next`, `react`).
  - `devDependencies` are needed only to build, check, or test (`typescript`, `eslint`).
- `package-lock.json`: the exact version of every installed package (including dependencies of dependencies). **Commit it** so every machine and Vercel installs identical versions.
- `tsconfig.json`: TypeScript settings. `"paths": { "@/*": ["./src/*"] }` lets us write `@/components/ui/button` instead of `../../components/ui/button`.
- `next.config.ts`: Next.js settings (empty for now).
- `next-env.d.ts` and `.next/`: generated by Next. Git-ignored.

### App Router routing
- Every folder inside `src/app/` is a URL segment. A folder becomes a visitable page only when it contains `page.tsx`.
  - `src/app/page.tsx` → `/`
  - `src/app/about/page.tsx` → `/about`
- `layout.tsx` wraps every page beneath it. The root layout renders `<html>` and `<body>` and is **never re-mounted** when navigating between pages.
- Later, `route.ts` files create API endpoints the same way (`src/app/api/categories/route.ts` → `/api/categories`).

### Server vs. Client Components (first look)
- In the App Router, components are **Server Components by default**: they run on the server, produce HTML, and send no component JavaScript to the browser.
- A file starting with `"use client"` becomes a **Client Component**: it is also sent to the browser so it can use state, effects, and event handlers (`onClick`).
- Our Phase 1 page is a Server Component, which is why its buttons are `disabled`. Interactivity comes in Phase 2.

### Static vs. dynamic rendering
- `npm run build` showed `○ /  (Static)`: the page had no request-specific data, so Next rendered it **once at build time**.
- Once a page reads the database or cookies (Phase 3), it becomes `ƒ (Dynamic)`, rendered per request.

### Generated route types
- `LayoutProps<"/">` and `PageProps<"/...">` are **global types Next generates** from your routes during `next dev`, `next build`, or `next typegen`.
- Before the first run they don't exist, so the editor shows `Cannot find name 'LayoutProps'`. **Not a bug; the types just haven't been generated yet.**
- That's why our `typecheck` script is `next typegen && tsc --noEmit`.

### Tailwind CSS 4
- Utility classes (`flex`, `gap-3`, `text-muted-foreground`) are written in JSX; Tailwind scans the files and generates only the CSS actually used.
- v4 is configured **in CSS**, not JavaScript: `@import "tailwindcss";` in `globals.css`, and theme values in `@theme`.
- Here it plugs into Turbopack via `@tailwindcss/turbopack`, so there's no `postcss.config.mjs` and no `tailwind.config.js`.

### shadcn/ui
- **Not** a component library you install and import from `node_modules`. The CLI **copies component source into your project** (`src/components/ui/`). You own it and can edit it.
- `components.json` tells the CLI where to put files and which style/base to use.
- Under the hood: **Radix** provides accessible behavior (focus, keyboard, ARIA); **Tailwind** provides styling; **class-variance-authority** maps props like `variant="outline"` to classes; **`cn()`** merges class names so `className` overrides win cleanly.
- Theme colors are CSS variables (`--primary`, `--muted-foreground`) in `globals.css`, which is why classes like `text-muted-foreground` work in light and dark mode.

### Environment variables
- `.env` holds real values locally and is **git-ignored**.
- `.env.example` lists the variable **names** with fake values and **is committed**, so others know what to set.
- Variables are server-only by default. Only those prefixed `NEXT_PUBLIC_` are bundled into browser JavaScript. **A secret must never have that prefix.**
- Gotcha we hit: the template's `.gitignore` rule `.env*` also ignored `.env.example`. Fixed with the negation `!.env.example`.

### Supply-chain hygiene
- Before trusting a new short-named package (`cn`), check it: `npm view cn repository.url maintainers dependencies`.
- Typosquatting = malicious packages with names close to popular ones. Check the publisher and repository.

### Reading tool output
- npm deprecation **warnings** are not errors. Check the final lines ("found 0 vulnerabilities", exit code).
- When a command fails, **read the full error first**. `Invalid preset: radix-nova. Available presets: nova, …` told us the fix directly.
- Libraries rename things between major versions (Lucide's `CircleHelp` → `CircleQuestionMark`). Check the installed package rather than memory or old tutorials.
- On Windows, `npx` starts Node as a grandchild process; stopping the parent can leave the server running. Check with `Get-NetTCPConnection -LocalPort <port>`.

### Git basics
- `.gitignore` lists what must never be committed (`node_modules`, `.next`, `.env`).
- Before every commit, check `git status` / `git diff --staged` to make sure no secrets are staged.
